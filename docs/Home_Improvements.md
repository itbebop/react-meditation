# 홈 화면 관리 (`AdminHome.jsx`) 개선 사항

홈 화면 슬라이드 이미지와 관리자 "홈 화면" 메뉴에 관한 문제 목록과 개편 계획입니다.
전체 개선 목록은 [IMPROVEMENTS.md](IMPROVEMENTS.md), 완료한 작업의 상세 기록은 [WORKLOG.md](WORKLOG.md)에 있습니다.

- 2026-11-23 코드 검토와 운영 Storage `home/` 파일 목록(읽기만)으로 정리했습니다.
- 운영 `home/` 파일: `PC1`(png, 2.3MB), `PC2`, `PC3`, `Mobile1`(png, 2.6MB), `Mobile2`, `mobileImg1`, `pcImg1`. 모두 확장자가 없습니다.

## 🔴 올려도 홈 화면에 안 나옴 (해결함)

- [x] **H1. 업로드 파일 이름에 `.png`가 붙어서 홈·관리자 화면 모두 못 찾음**
  - 원인: 2025-11-14 커밋 `cd23286`에서 업로드 경로가 `home/PC1`에서 `home/PC1.png`로 바뀌었습니다. 이 코드는 2026-11-23 PR #1 배포 때 운영에 처음 반영됐습니다.
  - 홈(`Home.jsx`)은 정확히 `PC<숫자>`인 파일만 읽고, 관리자 화면은 `PC1`이 있는지만 확인합니다.
  - 그래서 업로드하면 "성공" 메시지와 미리보기는 나오지만 **홈 화면은 그대로**였습니다. 새로고침하면 관리자 화면에도 예전 이미지가 다시 보였습니다.
  - 삭제는 `.png`가 없는 `PC1`을 지웠습니다.
  - 2026-11-23 기준으로 `.png` 파일은 아직 없어서 실제 업로드 피해는 없었습니다.
  - → 2026-11-23 해결: 업로드 이름을 확장자 없는 `PC<번호>`로 되돌려, 불러오기·삭제와 같은 이름을 씁니다. 2026-11-25 운영에 배포했습니다 (WORKLOG 참고).
- [x] **H2. 모바일 이미지는 관리자에서 올려도 홈에 나오지 않음**
  - 관리자 화면은 `Mobile1~5`를 관리하지만, 홈 모바일 화면은 `mobileImg<숫자>`만 읽습니다.
  - 지금 모바일 홈에는 2025-04-16에 올린 `mobileImg1` 한 장만 나옵니다. 이 파일은 관리자 화면에서 보거나 바꿀 수 없었습니다.
  - 관리자 화면의 `Mobile1`, `Mobile2`와 `pcImg1`은 어디에도 쓰이지 않습니다.
  - → 2026-11-23 해결: 관리자 모바일 칸이 홈에서 읽는 `mobileImg<번호>` 파일을 쓰도록 바꿨습니다. 2026-11-25 운영에 배포했습니다.
    - 홈 화면 코드는 그대로라 홈 모습은 바뀌지 않았습니다.
    - `Mobile1`·`Mobile2`·`pcImg1`은 삭제하지 않고 남겨 두었습니다 (WORKLOG 참고).

## 🟠 실수하기 쉬움

- [ ] **H3. 업로드·삭제가 즉시 운영에 반영되고 확인이 없음**: 업로드 버튼을 누르면 바로 덮어씁니다. 삭제도 확인 창 없이 바로 지워져서 되돌릴 수 없습니다.
- [ ] **H4. 파일 검사가 동작하지 않음**
  - 형식·5MB 검사 함수(`handleFileChange`)가 있지만 쓰이지 않아서, 어떤 파일이든 올라갑니다.
  - 지금 `PC1`은 2.3MB, `Mobile1`은 2.6MB PNG라서 첫 화면 로딩이 무겁습니다.
  - 참고: 2026-11-24 만든 `src/utils/imageResize.js`(자동 줄이기)와 `src/components/imageCrop/`(자르기 창)을 홈에도 그대로 쓸 수 있습니다.
- [ ] **H5. 파일 선택 후 "업로드"를 따로 눌러야 함**: 선택만 하고 업로드를 누르지 않아도 경고가 없습니다. 올리기 전 미리보기도 없습니다.
- [ ] **H6. 업로드 중 버튼이 막히지 않음**: 여러 번 누르면 업로드가 겹칩니다. 불러오는 중 표시도 없습니다.
- [ ] **H7. 권장 크기 안내가 불완전**
  - 제목이 "홈 이미지 업로드 (1920 x 1080 / )"로 끝나 있고, 모바일 권장 크기가 없습니다.
  - 홈은 이미지를 `object-cover`로 잘라서 보여 주는데(PC 높이 550~600px, 모바일 540px), 어디가 잘리는지 알 수 없습니다.
- [ ] **H8. "이미지 1 (PC 및 Mobile)" 묶음이 실제와 다름**: 홈의 PC 슬라이드와 모바일 슬라이드는 서로 독립적이라 장수가 달라도 됩니다. 그런데 화면은 한 쌍처럼 보입니다.

## 🟡 불편함

- [ ] **H9. 올린 이미지가 기본으로 접혀 있음**: "이미지 보기"를 눌러야 보이고, 슬라이드 전체를 한눈에 볼 수 없습니다. 순서를 바꾸려면 다시 올리는 방법뿐입니다.
- [ ] **H10. 모든 이미지를 지우면 홈에 깨진 이미지가 나옴**: 이미지가 없을 때 `/default_pc.jpg`, `/default_mobile.jpg`를 쓰는데, 이 파일이 `public/`에 없습니다.
- [ ] **H11. 기타 코드**: 상태 배열을 얕은 복사로 직접 고쳐서 화면 갱신이 빠질 수 있습니다. `Home.jsx`에 `console.log("현재 상태")`가 남아 있습니다.
- [ ] **H12. PC 슬라이드 이미지 일부가 작거나 세로형이라 흐리게 보임**
  - PC 슬라이드는 1440px 화면에서 1153×600(가로:세로 1.92:1)으로 표시됩니다.
  - 운영 `PC2`는 512×768(세로형), `PC3`는 394×337(작음)이라 2~3배 확대되고 위아래가 많이 잘립니다.
  - PC용은 가로형 1920×1000 이상을 권장합니다.
- [ ] **H13. 모바일 슬라이드 이미지에 잡지 로고(VOGUE)가 들어 있음**: 운영 `mobileImg1`(800×930) 위쪽에 "VOGUE" 글자가 보입니다. 잡지 사진을 가져온 것이라면 저작권 문제가 될 수 있습니다. 직접 찍었거나 사용 허가를 받은 이미지로 바꾸는 것을 권장합니다.

## PC·모바일 이미지를 따로 넣는 불편함 해소 방안 (2026-11-23 검토)

**왜 따로 넣게 되어 있는지**: 운영 화면에서 잰 슬라이드 크기는 다음과 같습니다.

| 화면 | 슬라이드 크기 | 가로:세로 |
|---|---|---|
| PC (1440px) | 1153×600 | 1.92 : 1 (넓은 가로형) |
| 태블릿 (768px) | 641×550 | 1.17 : 1 |
| 휴대폰 (375px) | 343×540 | 0.64 : 1 (세로형) |

- PC와 휴대폰의 모양이 반대라서, 같은 이미지를 쓰면 휴대폰에서는 가운데만 보입니다. 1.5:1 사진이면 가운데 약 43%, 1.92:1 사진이면 약 1/3입니다.
- 지금 홈 이미지들은 글자가 없는 사진이고 인물·사물이 가운데 있어서, 가운데만 보여도 크게 어색하지 않습니다.

| 방법 | 관리자가 할 일 | 장점 | 단점 |
|---|---|---|---|
| **A. 한 장 + 휴대폰에서 보일 부분 고르기 (추천)** | 이미지 한 장을 올리고 "왼쪽 / 가운데 / 오른쪽" 버튼 중 하나를 누름 | 올리는 이미지가 한 장뿐. 휴대폰 모양 미리보기로 바로 확인. 나중에 위치만 바꿀 수 있음 | 위치 정보를 저장할 곳이 필요해서 아래 전체 개편과 함께 해야 함 |
| B. 한 장 올리면 휴대폰용을 자동으로 잘라 만들기 | A와 같음 | 결과는 A와 같음 | 파일이 두 개 생기고, 위치를 바꾸려면 다시 만들어야 함 |
| C. 휴대폰에서도 자르지 않고 가로형 그대로 보여 주기 | 한 장만 올림 | 가장 간단함 | 휴대폰 홈의 슬라이드 높이가 540px에서 약 180~230px로 낮아져 방문자 화면이 크게 바뀜(디자인 변경 확인 필요) |

- A는 개발 원칙 10번(고연령·비전문가 사용자)에도 맞습니다. 올리는 것은 한 장이고, 고르는 것도 큰 버튼 하나입니다. 꼭 필요할 때만 "휴대폰용 따로 넣기"를 쓰면 됩니다.
- A를 택해도 홈 화면은 휴대폰 전용 이미지가 있으면 지금처럼 그것을 보여 주므로, 기존 화면은 바뀌지 않습니다.
- **구현 위치**: 휴대폰에서 보일 위치를 저장해야 하므로, 아래 "전체 개편 계획"의 `pages/home` 슬라이드 목록에 함께 넣는 것이 자연스럽습니다. 슬라이드마다 이미지 1장, 휴대폰 위치, 선택적인 휴대폰용 이미지를 저장합니다.
- A를 택하면 개편 계획의 "PC와 모바일은 장수·순서를 따로 정함"은 "슬라이드 하나에 PC·휴대폰을 함께"로 바뀝니다.

## 전체 개편 계획 (2026-11-23 정리, 보류)

H1·H2만 먼저 고쳤고, 나머지 H3~H11은 아래 계획으로 함께 해결합니다. 진행할 때 개발 원칙 10번(고연령·비전문가 사용자)을 기준으로 다시 다듬습니다.

**1. 파일 이름 대신 "슬라이드 목록"으로 관리**
- Firestore `pages/home` 문서에 PC 슬라이드 목록과 모바일 슬라이드 목록을 순서대로 저장합니다(이미지 주소, 파일 경로).
- 새 이미지는 `home/slides/pc/<시각>.jpg`처럼 매번 다른 이름으로 올립니다. 그러면 덮어쓰기나 이름 불일치가 생기지 않습니다.
- PC와 모바일은 장수·순서를 따로 정합니다 (H8). 위의 A안을 택하면 바뀝니다.

**2. 관리자 화면**
- PC/모바일 탭별로 썸네일을 표시 순서대로 한 줄에 보여 줍니다. 끌기와 화살표 버튼으로 순서를 바꾸고, 빼기도 할 수 있습니다 (H9).
- 여러 장을 한 번에 추가하고, 형식·용량을 검사하고(H4), 올리기 전에 썸네일로 미리 보여 줍니다(H5).
- 자동 줄이기: 가로 최대 1920px로 줄여서 올립니다(H4). 다른 화면에서 쓰는 `utils/imageResize.js`를 그대로 씁니다.
- 추가·삭제·순서 변경은 먼저 화면에만 반영합니다 (H3, H6).
  - "홈에 반영"을 눌러 확인한 뒤 한 번에 저장합니다.
  - "되돌리기"가 있고, 저장하지 않고 나가면 경고합니다.
- 홈과 같은 슬라이드 부품으로 실제 높이(PC 550~600px, 모바일 540px)에서 미리 보여 주고, 잘리는 부분을 확인할 수 있게 합니다 (H7).
- "홈에 쓰이지 않는 이미지"(`Mobile1`, `Mobile2`, `pcImg1` 등)를 보여 주고, 눌러서 슬라이드에 추가할 수 있게 합니다.
- 슬라이드에서 뺀 이미지는 바로 지우지 않고 보존합니다. 영구 삭제는 확인을 받은 뒤 따로 합니다.

**3. 홈 화면**
- `pages/home` 문서가 있으면 그 목록대로 보여 주고, **없으면 지금 방식 그대로** 보여 줍니다. 그래서 관리자가 처음 저장하기 전까지 홈은 바뀌지 않습니다.
- 홈 슬라이드(Carousel)를 공용 부품으로 분리해서 관리자 미리보기와 함께 씁니다. 분리 전후 HTML을 비교해서 확인합니다.
- 이미지가 0장이면 슬라이드 영역을 숨기고(H10), `console.log`를 지웁니다(H11).

**4. 진행 순서**
1. 슬라이드 부품 분리
2. `pages/home` 모듈 만들기(문서가 없으면 기존 방식)
3. 관리자 화면
4. Emulator에 운영과 같은 `home/` 구성을 만들어 확인
5. 기록·PR·배포
6. 배포 후 첫 "홈에 반영" 확인
7. 안정된 뒤 사용하지 않는 파일 정리
