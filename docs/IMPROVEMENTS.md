# 개선 필요 사항

코드 검토, `npm audit`, `npm run lint` 결과를 바탕으로 정리한 수정 목록입니다(2026-11-23 기준).
Firestore 보안 규칙과 Firebase Auth 설정(회원가입 허용 여부)은 콘솔에서만 관리되어 저장소에서 확인하지 못했습니다.

## 🔴 1순위: 보안

- [x] **오타 난 외부 스크립트 주소**: `index.html`이 `https://cdn.tailwindscss.com`(`tailwindcss`가 아닌 `tailwindscss`)에서 스크립트를 불러왔습니다. 연결 시간 초과(약 20초)로 끝났지만, 누군가 이 도메인을 등록하면 모든 방문자 브라우저에서 임의의 JS가 실행될 수 있었습니다. → `<script>` 줄 삭제 (2026-11-23). Tailwind는 빌드에 포함되어 있어 스타일 변화 없음(CSS 빌드 결과 동일), 개발 서버 페이지 로드 약 20초 → 0.2초.
- [ ] **관리자 권한 확인 누락**: 로그인 화면(`Login.jsx`)만 `user` 컬렉션을 확인하고, `ProtectedRoute.jsx`는 로그인 여부만 봅니다. 로그인한 계정이면 누구나 `/dashboard`에 직접 들어갈 수 있고, 회원가입이 켜져 있으면 아무나 계정을 만들어 접근할 수 있습니다.
  - 위치: `src/components/pages/admin/ProtectedRoute.jsx`
- [ ] **Storage 쓰기 권한이 "로그인 사용자 전체"**: 관리자가 아닌 계정도 홈·소개·강의 이미지를 덮어쓸 수 있습니다. `user` 컬렉션 또는 custom claim 기준으로 제한해야 합니다.
  - 위치: `storage.rules`
- [ ] **Firestore 규칙이 저장소에 없음**: `alarms`에 신청자 이름·전화번호·이메일이 저장됩니다. 규칙이 느슨하면 개인정보가 노출됩니다. 콘솔 규칙을 확인하고 `firestore.rules`로 저장소에서 관리하도록 옮깁니다.
- [x] **npm 취약점**: 27개(critical 2) → 4개(high, 모두 `@grpc/grpc-js` 계열)로 줄임. 자세한 내용은 [WORKLOG.md](WORKLOG.md) 참고.

- [x] **`pages` 컬렉션(협회 소개 에디터) 쓰기 권한 확인**: 2026-11-23 운영에서 관리자 저장 성공(사용자 확인). 단, 관리자가 아닌 로그인 사용자도 쓸 수 있는지는 콘솔 규칙 확인이 필요합니다(1순위 권한 문제와 함께). (읽기는 비로그인으로도 허용됨을 확인: REST 요청 → 404 = 권한 있음·문서 없음)

> 1~3번은 "관리자 = `user` 컬렉션(또는 custom claim)"이라는 하나의 기준으로 묶어서, 보호 라우트·Storage 규칙·Firestore 규칙이 모두 그 기준을 쓰게 하는 것이 좋습니다.

### 🟠 실수하기 쉬움
- [ ] **H3. 업로드·삭제가 즉시 운영에 반영되고 확인이 없음**: 업로드 버튼을 누르면 바로 덮어쓰고, 삭제도 확인 창 없이 즉시 지움(되돌릴 수 없음).
- [ ] **H4. 파일 검사가 동작하지 않음**: 형식·5MB 검사 함수(`handleFileChange`)가 있지만 쓰이지 않아 어떤 파일이든 올라감. 현재 `PC1` 2.3MB, `Mobile1` 2.6MB PNG로 첫 화면 로딩이 무거움.
- [ ] **H5. 파일 선택 후 "업로드"를 따로 눌러야 함**: 선택만 하고 업로드를 안 눌러도 경고가 없고, 올리기 전 미리보기도 없음.
- [ ] **H6. 업로드 중 버튼이 막히지 않음**: 여러 번 누르면 업로드가 겹침. 불러오는 중 표시도 없음.
- [ ] **H7. 권장 크기 안내가 불완전**: 제목이 "홈 이미지 업로드 (1920 x 1080 / )"로 끝나 있고 모바일 권장 크기가 없음. 홈은 `object-cover`로 잘라서 보여주는데(PC 높이 550~600px, 모바일 540px) 어디가 잘리는지 알 수 없음.
- [ ] **H8. "이미지 1 (PC 및 Mobile)" 묶음이 실제와 다름**: 홈의 PC·모바일 슬라이드는 서로 독립적이라 장수가 달라도 되는데, 화면은 한 쌍처럼 보임.

### 🟡 불편함
- [ ] **H9. 올린 이미지가 기본으로 접혀 있음**: "이미지 보기"를 눌러야 보이고, 슬라이드 전체를 한눈에 볼 수 없음. 순서 변경은 다시 올리는 방법뿐.
- [ ] **H10. 모든 이미지를 지우면 홈에 깨진 이미지**: 이미지가 없을 때 `/default_pc.jpg`, `/default_mobile.jpg`를 쓰는데 이 파일이 `public/`에 없음.
- [ ] **H11. 기타 코드**: 상태 배열을 직접 수정(얕은 복사)해서 화면 갱신이 누락될 수 있음, `Home.jsx`에 `console.log("현재 상태")` 남아 있음.

- [ ] **H12. PC 슬라이드 이미지 일부가 작거나 세로형이라 흐리게 보임**: PC 슬라이드는 1440px 화면에서 1153×600(가로:세로 1.92:1)으로 표시되는데, 운영 `PC2`는 512×768(세로형), `PC3`는 394×337(작음)이라 2~3배 확대되고 위아래가 많이 잘림. PC용은 가로형 1920×1000 이상 권장.
- [ ] **H13. 모바일 슬라이드 이미지에 잡지 로고(VOGUE)가 들어 있음**: 운영 `mobileImg1`(800×930) 상단에 "VOGUE" 글자가 보임. 잡지 사진을 가져온 것이라면 저작권 문제가 될 수 있어 직접 찍거나 사용 허가된 이미지로 바꾸는 것을 권장.

### PC·모바일 이미지를 따로 넣는 불편함 해소 방안 (2026-11-23 검토)

운영 화면에서 잰 슬라이드 크기: PC(1440px) 1153×600 = 1.92:1, 태블릿(768px) 641×550 = 1.17:1, 휴대폰(375px) 343×540 = 0.64:1. PC와 휴대폰의 모양이 반대라 같은 이미지를 쓰면 휴대폰에서는 가운데만 보임(1.5:1 사진이면 가운데 약 43%, 1.92:1 사진이면 약 1/3). 현재 이미지들은 글자 없는 사진이고 인물·사물이 가운데 있어 가운데만 보여도 크게 어색하지 않음.

- **A. 한 장만 올리고, 휴대폰에서 보일 부분을 버튼으로 고르기 (추천)**: 모바일용을 따로 올리지 않으면 PC 이미지를 휴대폰에도 자동으로 사용. 관리자는 "왼쪽 / 가운데 / 오른쪽" 큰 버튼으로 휴대폰에서 보일 부분을 고르고 휴대폰 모양 미리보기로 확인. 꼭 필요할 때만 "휴대폰용 따로 넣기"를 선택. 이미지 파일은 하나, 나중에 위치만 바꿀 수 있음. 홈 화면은 모바일 전용 이미지가 있으면 지금처럼 그것을 보여 주므로 기존 화면 변화 없음.
- **B. 한 장 올리면 휴대폰용 이미지를 자동으로 잘라서 만들기**: A와 같은 위치 선택으로 휴대폰용 파일을 따로 만들어 저장. 결과는 A와 같지만 파일이 두 개 생기고 위치를 바꾸려면 다시 만들어야 함.
- **C. 휴대폰에서 이미지를 자르지 않고 가로형 그대로 보여 주기**: 한 장이면 충분하지만 휴대폰 홈의 슬라이드 높이가 540px → 약 180~230px로 낮아져 방문자가 보는 화면이 크게 바뀜(디자인 변경 확인 필요).
- 구현 위치: 위치 정보를 저장해야 하므로 아래 "전체 개편 계획"의 `pages/home` 슬라이드 목록에 함께 넣는 것이 자연스러움(슬라이드마다 이미지 1장 + 휴대폰 위치 + 선택적 휴대폰용 이미지). 개편 계획의 "PC와 모바일은 장수·순서를 따로 정함"은 A를 택하면 "슬라이드 하나에 PC·휴대폰을 함께"로 바뀜.

### 전체 개편 계획 (2026-11-23 정리, 보류 — H1·H2만 먼저 수정함)

H3~H11을 함께 해결하기 위한 계획입니다. 진행 시 개발 원칙 10번(고연령·비전문가 사용자)을 기준으로 다시 다듬습니다.

**1. 파일 이름 대신 "슬라이드 목록"으로 관리**
- Firestore `pages/home` 문서에 PC 슬라이드 목록과 모바일 슬라이드 목록을 순서대로 저장(이미지 주소, 파일 경로)
- 새 이미지는 `home/slides/pc/<시각>.jpg`처럼 매번 다른 이름 → 덮어쓰기·이름 불일치 없음
- PC와 모바일은 장수·순서를 따로 정함 (H8)

**2. 관리자 화면**
- PC/모바일 탭별 썸네일 줄(표시 순서대로), 끌기 + 화살표 버튼으로 순서 변경, 빼기 (H9)
- 여러 장 추가, 형식·용량 검사(H4), 올리기 전 썸네일 미리보기(H5)
- 자동 압축: 가로 최대 1920px JPEG로 줄여서 업로드 (H4)
- 추가·삭제·순서 변경은 화면에만 반영 → "홈에 반영"으로 확인 후 한 번에 저장, "되돌리기", 미저장 시 이탈 경고 (H3, H6)
- 홈과 같은 슬라이드 부품으로 실제 높이(PC 550~600px, 모바일 540px) 미리보기, 잘리는 부분 확인 (H7)
- "홈에 쓰이지 않는 이미지"(`Mobile1`, `Mobile2`, `pcImg1` 등)를 보여 주고 눌러서 슬라이드에 추가
- 슬라이드에서 뺀 이미지는 바로 지우지 않고 보존, 영구 삭제는 확인 후 별도

**3. 홈 화면**
- `pages/home` 문서가 있으면 그 목록대로, **없으면 지금 방식 그대로** → 관리자가 처음 저장하기 전까지 홈 변화 없음
- 홈 슬라이드(Carousel)를 공용 부품으로 분리해 관리자 미리보기와 함께 사용(분리 전후 HTML 비교로 확인)
- 이미지가 0장이면 슬라이드 영역 숨김 (H10), `console.log` 제거 (H11)

**4. 진행 순서**: 슬라이드 부품 분리 → `pages/home` 모듈(문서 없으면 기존 방식) → 관리자 화면 → Emulator에 운영과 같은 `home/` 구성으로 확인 → 기록·PR·배포 → 배포 후 첫 "홈에 반영" 확인 → 안정 후 사용 안 하는 파일 정리
